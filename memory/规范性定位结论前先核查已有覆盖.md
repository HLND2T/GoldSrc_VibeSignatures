# 规范性定位结论前先核查已有覆盖

## 触发信号
- 用户提到某函数/全局符号"已被项目 cover / 是已知数据 / 已有产物"，或准备为新符号设计 finder；
- 自己准备输出"应该 / 不应该 / 必须重新定位 / 完整正确写法是……"这类规范性结论；
- 准备为某 owning function 新建字符串锚 finder。

## 根因（2026-09-06 案例：cl_resourcesonhand）
为 `cl_resourcesonhand` 设计定位链时，只查了 `bin/<tag>/engine/`（工作副本，无该 yaml）就默认 owning function `CL_PrecacheResources` 未被覆盖，进而错误反驳用户提出的复用方案。实际 `ida_preprocessor_scripts/find-CL_PrecacheResources.py` 存在、`configs/*.yaml` 全版本注册、`bin_artifacts/<tag>/engine/CL_PrecacheResources.{windows,linux}.yaml` 双平台产物俱在。三个叠加偏差：
1. **信息缺口**：未查 `ida_preprocessor_scripts/`、`configs/`、`bin_artifacts/` 三处覆盖面（`bin/` 只是工作副本，产物在 `bin_artifacts/`）。
2. **解读错位**：把用户说的 "LLM_DECOMPILE" 按 SKILL.md 严格义（predecessor 反编译 fallback）理解，而项目语境里指 `find-XXX-decompiles` 家族（config skills 段的 `expected_input → expected_output` 复用机制）。
3. **规则过紧**：把 `old_yaml_map=None`（禁**同名旧产物**用 func_sig 绕过发现链）外推成"禁止复用任何已 cover 函数"。SKILL.md 明确允许 predecessor 用 "its own stable string **or existing artifact**" 定位。

## 正确做法
1. 给规范性结论前先跑覆盖面三查：
   - `ls ida_preprocessor_scripts | grep -i <symbol>`（finder 是否存在）
   - `grep -n <symbol> configs/<tag>.yaml`（skills 段注册 + gamesymbol 清单）
   - `find bin_artifacts -iname "*<symbol>*"`（产物是否已生成，注意不是 `bin/`）
2. owning function 已被 cover 时，gv/下游符号 finder 走**复用模式**而非重复字符串发现：config 声明 `expected_input: <OwnerFunc>.{platform}.yaml`，脚本以 `find-CBaseUI__Initialize-decompiles.py` 为模板——读产物 `func_va` → 当前 IDB 用 `_inspect_function_via_mcp` 重校验（函数起点 + func_sig，不符即 fail closed）→ 函数内确定性操作数恢复 → `write_gv_yaml`（`gv_sig` 用 owner 的 func_sig + `gv_inst_offset/length/disp`）。该模板 docstring 明确 "avoids an unnecessary LLM dependency"。
3. skill 规则与工程直觉/用户提示冲突时，先在仓库找现行先例（`-decompiles` 系列、`xref_funcs` 用法如 `find-NLoadBlobFile.py`）再下结论，不把规则读得更紧。
4. 区分两种 "LLM_DECOMPILE"：SKILL.md 严格义（predecessor 反编译 fallback，仅当无直锚时）与项目 `-decompiles` 命名家族（消费已有产物恢复下游符号，实现上可完全确定性、无 LLM）。

## 验证方式
覆盖三查有命中且产物存在 → 复用链成立；恢复规则在当前 IDB 唯一收敛（如 cl_resourcesonhand 的配对引用规则在 hw.dll/hw.so 各解出唯一哨兵值）才算数。

## 适用范围
`find-anchor-to-goldsrc-symbol` 类任务、新 finder 设计、gamesymbol 清单规划、以及任何"要不要为某符号建锚"的判断。不属于本仓库符号体系的任务不适用。
