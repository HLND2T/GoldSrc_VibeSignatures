# Gamedata generator contract

## Overview

Each enabled generator lives at `gamedata-generators/<directory>/gamedata.py`. Generators are invoked by
`update_gamedata.py` and are also exercised as a self-consistency gate during PR validation. The surrounding candidate/
manifest/guard boundary is described in [[Canonical gamedata bootstrap]]; this note covers only the generator API
contract itself.

## API contract

```python
MODULE_NAME = "example"
GENERATOR_API_VERSION = 2
OUTPUT_PATHS = ("gamedata.txt",)


def update(symbol_store, output_dir, *, context):
    payload = symbol_store.require("engine", "example.windows.yaml")
    (output_dir / "gamedata.txt").write_text(str(payload), encoding="utf-8")
```

- `MODULE_NAME` declares the owning module.
- `GENERATOR_API_VERSION = 2` opts into the current contract. API v1 omits `GENERATOR_API_VERSION` and the `context`
  keyword — treat a v1 file as legacy, not as the pattern to copy.
- `OUTPUT_PATHS` lists every file the generator may write; every output must be a declared relative path with an
  allowed data-file extension.
- `update(symbol_store, output_dir, *, context)` receives a read-only `SymbolStore` (returns copies; never mutate it),
  a per-generator owned output directory, and a keyword-only `context` carrying the immutable game version and snapshot
  binary metadata.

## Runner rules

The runner gives each generator its own directory and rejects missing, extra, linked, or escaping output paths. Source
and output inventories are hashed in the candidate session, so changing a generator, config, symbol candidate, or
generated byte invalidates the gamedata guard.

An absent or empty generator root is valid and produces an empty, hashed inventory. That empty inventory satisfies the
gamedata step only after `gamedata_candidate.py guard` succeeds and the game-symbol candidate is explicitly marked
(`mark -step gamedata`).

## Validation

Gamedata candidate/contract tests cover empty and declared payload inventories, generator drift, tamper, extra bundle
files, and the guard/mark sequence. Run them with the repository-contract suite (see [[test 文件必须登记到测试分组]]).
