# Gamedata generator contract

Each enabled generator lives at `gamedata-generators/<directory>/gamedata.py` and declares:

```python
MODULE_NAME = "example"
GENERATOR_API_VERSION = 2
OUTPUT_PATHS = ("gamedata.txt",)


def update(symbol_store, output_dir, *, context):
    payload = symbol_store.require("engine", "example.windows.yaml")
    (output_dir / "gamedata.txt").write_text(str(payload), encoding="utf-8")
```

API v1 omits `GENERATOR_API_VERSION` and the `context` keyword. `GeneratorContext` contains the immutable game version
and snapshot binary metadata. The `SymbolStore` is read-only and returns copies.

Every output must be a declared relative path with an allowed data-file extension. The runner gives each generator its
own directory and rejects missing, extra, linked, or escaping output paths. Source and output inventories are hashed in
the candidate session. Changing a generator, config, symbol candidate, or generated byte invalidates the guard.

An absent or empty generator root is valid and produces an empty, hashed inventory. This still satisfies the gamedata
step only after `gamedata_candidate.py guard` succeeds and the game-symbol candidate is explicitly marked.
